# 运行维护与排错

[文档导航](README.md) · [项目首页](../README.md)

本文档中的命令均从仓库根目录执行。

## 运维与排错

服务默认监听 `127.0.0.1:8000`，用于本机实验和 SSH 转发访问。当前接口提供推理、会话、流式输出和取消功能。

| 现象 | 检查顺序 |
| --- | --- |
| 找不到 `autellix-serve` 或包 | 检查当前 Python 和激活环境，重新执行该环境的可编辑安装 |
| 后端版本拒绝启动 | 使用对应锁文件和独立环境，按后端迁移流程更新适配 |
| CUDA 不可用 | 检查 `nvidia-smi`、Torch CUDA 状态及进程设备配置；后端不提供假推理回退 |
| 初始化显存不足 | 检查模型大小、其他 GPU 进程、上下文和内存比例；共享 GPU 的副本预算需要合计考虑 |
| 整段 prefill 超过 token 预算 | vLLM paper 模式增大 `max_num_batched_tokens` 或缩短输入，同时确认显存足够 |
| 窗口 KV 预留不足 | 降低批次、K 或 N，或增加可用 KV 显存；记录调整后的配置 |
| SGLang 主机 KV 预算耗尽 | 根据已换出 KV 量调整 `autellix_swap_space` 与并发容量 |
| 聊天模板错误 | 使用提供 chat template 的模型；直接 Python 的 `prompt`/`input_ids` 路径可用于原始文本 |
| 后续调用的继承历史为 0 | 检查是否复用了 session，前一调用是否完成，以及是否选择了 `plas`/`atlas` |
| 流式内容不完整 | 检查服务器错误、连接关闭、结束原因和 `[DONE]` |
| 状态表残留或 SQLite 错误 | 确认无活动服务使用该目录，检查进程退出情况及文件系统位置，换用新的状态目录复测 |

### 状态与日志

指定 `state_dir` 后，目录通常含 `programs.sqlite`、SQLite 的 WAL/SHM 文件，以及 `replica-*.jsonl`。未指定时会创建临时状态目录。目录用于进程协调与诊断，不是崩溃后可恢复生成任务的检查点；服务重启建议使用新目录，旧目录在确认无进程使用后再清理。

通过 `GET /sessions` 查看程序服务历史、活动调用、引擎和时间戳。通过 trace 的 `admit`、`demote`、`promote`、`schedule_window`、`execute`、`swap_out`、`resume`/`swap_in`、`reserve`、`refill` 等事件检查实际路径；事件是否出现取决于后端、配置和负载。

记录 bug 时保留：Git 提交、后端及 Torch 版本、模型标识/版本、启动参数、最小输入、相关异常和 trace。提交源码与必要的实验记录；模型权重和虚拟环境保存在运行机器上。

## 启停与资源回收流程

启动前检查 GPU 上是否已有任务，确认服务端口未冲突、模型路径有效，并为本次实例选用独立 Linux 状态目录。服务启动和模型加载可能耗时；首次健康检查成功后再提交业务调用。

正常停止时先停止新请求，等待或取消已有调用，结束业务会话，再退出服务或引擎上下文。重启时使用新状态目录；活动生成保存在当前进程中，重启后重新提交请求。

健康接口的 `status=ok` 表示有可用副本；`loads` 给出各副本负载。结合会话状态和 trace 定位积压。失败副本通过重启服务或创建新引擎恢复。

## 本地目录管理

| 内容 | 保留或清理建议 |
| --- | --- |
| 源码、测试、示例、锁文件、文档 | 受 Git 管理，作为后续开发基础保留 |
| `.git/` | 仓库历史与远程信息，不属于运行缓存 |
| 本地模型 | 保留仍使用的权重，放在 `outputs/models/` 或仓库外 |
| 虚拟环境与安装元数据 | 保留当前环境依赖和源码可编辑安装所需的 metadata |
| `__pycache__/`、测试缓存 | 无活动任务时可清理，可重新生成 |
| 当前实验 | 在 `outputs/` 下用独立实验目录保存计划与原始检查点 |
| 历史实验 | 在 `outputs/archive/h20/` 和 `outputs/archive/p40/` 保存已核对的归档及独有的原始结果。按需解包 |
| 复现资料 | 固定版本的数据与采集源码放在 `outputs/paper-sources/`，论文放在 `outputs/reference/` |
| 状态目录与 SQLite WAL/SHM | 确认无服务使用后一起处理，不在运行中单独删除数据库文件 |
| 临时脚本或下载的源码摘录 | 正式脚本已有替代且无引用后再清理 |

清理前应检查绝对路径及实际内容，避免把模型、环境或仍在运行的服务状态当临时数据。仓库忽略规则只控制提交行为，不会自动删除文件，也不说明被忽略文件都无用。

## 最小复现信息

排查问题时先记录 `git rev-parse HEAD`、Python/后端/Torch 版本、模型路径或固定模型 revision、GPU 型号与设备分组，再记录完整启动参数和最小请求。保留失败前后的 trace 和错误栈，而不是只保留最后一句报错。

如果同一提示只在抢占后错误，比较不中断输出、换入换出事件和窗口补位情况；如果会话无法回收，检查 Future 取消、worker 确认和程序关闭三个状态，定位尚未完成的回收步骤。
